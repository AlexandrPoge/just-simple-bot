# Модель базы знаний

## 1. Требования к статье

Текущая вкладка `Knowledge` в Google Таблице и автономный CSV используют одинаковые колонки: `id`, `status`, `equipment_aliases`, `topic_terms`, `exclude_terms`, `question_examples`, `answer`. Заголовки и порядок колонок менять нельзя. Вторая вкладка `Инструкция` поясняет правила редактирования.

Уже реализованы:

- стабильный уникальный `id`;
- `status`: `draft`, `published` или `archived`;
- названия оборудования через `|` (необязательное поле для общей ситуации);
- тематические слова/начала слов через `|`;
- исключающие слова через `|`;
- примеры вопросов через `|`;
- утверждённый текст ответа;

`title`, категория, версия, дата обновления и маршрут эскалации — возможные поля для следующего этапа, но в текущей таблице их нет.

## 2. Логическая модель

```text
KnowledgeArticle
├── id
├── title
├── category
├── equipment
├── examples[]
├── keywords[]
├── answer
├── source
├── status
├── version
├── updated_at
└── escalation_required
```

## 3. Правила содержания

1. Ответ должен быть официальным и проверенным.
2. В ответе нельзя оставлять неподтверждённые предположения.
3. Ссылки должны вести на утверждённые материалы.
4. Опасные ситуации должны иметь приоритетный и однозначный сценарий.
5. Одна статья должна отвечать на одну конкретную задачу.
6. Перед публикацией новую или изменённую статью проверяет ответственный сотрудник; формальная версия пока не ведётся.

## 4. Начальные статьи

### КАН Ультра

- Тема: очистка и обслуживание.
- Результат: ссылка на видеоинструкцию.
- URL: `https://youtu.be/WW1Hqh3_WNk`.

### КИТ

- Тема: периодичность обслуживания.
- Результат: обслуживание один раз в год.

### Переполнение

- Тема: первичная проверка переполненной станции.
- Результат: проверить электрический блок; при затоплении немедленно обесточить станцию и связаться с сервисным отделом.

## 5. Fallback-статья

Fallback не является обычной статьёй базы знаний. Это системный сценарий:

> В моей базе знаний нет информации по этому вопросу. Рекомендую обратиться в сервисный отдел компании для получения точной консультации.

Он используется при любом недостаточно уверенном совпадении.

Если вопрос явно об обслуживании станции, но модель не названа, бот задаёт только уточняющий вопрос. После ответа с названием модели поиск выполняется заново; неизвестная модель всё равно приводит к fallback. Контекст уточнения хранится до пяти минут и не переносится между чатами.

## 6. Жизненный цикл статьи

```text
draft → published → archived
```

Бот отвечает только по `published`. Формальная процедура согласования статей будет добавлена на следующем этапе. Если выбранная Google Таблица недоступна или строка некорректна, бот выдаёт безопасный отказ, а не ответ из старого CSV.
