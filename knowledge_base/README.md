# Локальная база знаний

Файл [articles.csv](articles.csv) нужен для автономного запуска бота без Google Таблицы. Его удобно открывать как таблицу в Excel, LibreOffice или редакторе CSV. Одна строка файла — одна статья. Заголовки столбцов менять нельзя.

Если в `.env` поле `GOOGLE_SHEET_ID` пустое, бот читает CSV при каждом вопросе. Сохранённые изменения в опубликованной статье применяются без перезапуска. Если `GOOGLE_SHEET_ID` заполнено, бот работает с Google Таблицей; CSV в этом режиме не используется и не синхронизируется с ней.

## Что заполнять

- `id` — уникальный идентификатор латиницей, например `kan_ultra_maintenance`.
- `status` — `draft`, `published` или `archived`. Бот отвечает только по `published`.
- `equipment_aliases` — варианты названия станции через `|`, например `кан ультра|кан`.
- `topic_terms` — слова или начала слов темы через `|`, например `почист|чист|обслуж`.
- `exclude_terms` — слова и фразы, при которых статья не подходит.
- `question_examples` — примеры вопросов через `|`.
- `answer` — готовый, утверждённый ответ. Бот выдаёт его без дополнений.

Чтобы добавить статью, создайте строку с новым `id` и статусом `draft`, заполните поля и проверьте текст. После смены статуса на `published` можно проверить ответ через Telegram. Пока статья в `draft`, бот её не использует.

CSV хранит каждую статью в одной физической строке. Если в ответе есть запятая или перенос строки, редактор CSV должен заключить поле в кавычки. При прямом редактировании файла проще пользоваться локальной веб-формой: она сама сохраняет корректный CSV.

Если нужен общий источник для разработчика и менеджера, используйте Google Таблицу. Перенос строк из локального CSV в неё сейчас выполняется вручную.
