# Service Knowledge Bot

Рабочий прототип Telegram-бота сервисного отдела. Он возвращает только утверждённые ответы из таблицы базы знаний. Неизвестные и неоднозначные вопросы получают безопасный отказ и сохраняются для разбора сотрудником.

## Запуск

Требуется Python 3.11 или новее. Локальный CSV-режим работает без сторонних библиотек; для Google Таблицы установите `python3 -m pip install -r requirements-google.txt`.

1. Создайте Telegram-бота через BotFather и получите токен.
2. Скопируйте `.env.example` в `.env` и укажите `TELEGRAM_BOT_TOKEN`.
3. Для общей Google Таблицы укажите `GOOGLE_SHEET_ID`, `GOOGLE_SHEET_TAB=Knowledge` и путь к JSON-ключу сервисного аккаунта в `GOOGLE_SERVICE_ACCOUNT_FILE`. Выдайте сервисному аккаунту роль «Редактор» только для этой таблицы. Без `GOOGLE_SHEET_ID` бот использует локальный CSV.
4. Проверьте подключение: `python3 -m service_bot --check` (проверяет Telegram, но не базу знаний).
5. Запустите бота: `python3 -m service_bot` (при старте проверяется доступ к базе знаний).
6. Откройте на этом же компьютере `http://127.0.0.1:8765` — локальный редактор базы знаний.

Для демонстрации хостинг не нужен. Оставьте терминал с ботом открытым: пока компьютер включён, процесс работает и есть интернет, бот доступен в Telegram. После остановки процесса бот перестанет отвечать. Для опроса Telegram должен быть запущен только один экземпляр бота.

Порт редактора меняется через `ADMIN_PORT` в `.env`. Для запуска без редактора используйте `python3 -m service_bot --no-admin`. Редактор слушает только `127.0.0.1` и не доступен другим компьютерам.

## Редактирование ответов без кода

Менеджер редактирует вкладку `Knowledge` в приватной Google Таблице. Разработчик может править ту же таблицу через локальный редактор. В Google-режиме это один источник: бот перечитывает таблицу при каждом вопросе, а локальная форма сохраняет прямо в неё. Перезапуск не нужен. При недоступности Google бот отвечает безопасным отказом; локальный CSV не подставляется вместо облачного источника.

Для автономной демонстрации без Google оставлен [knowledge_base/articles.csv](knowledge_base/articles.csv). В этом режиме форма сохраняет изменения в CSV. Чтобы переключиться на Google, добавьте `GOOGLE_SHEET_ID` и перезапустите процесс.

Колонки:

- `id` — постоянный уникальный идентификатор статьи;
- `status` — `draft`, `published` или `archived`; бот использует только `published`;
- `equipment_aliases` — названия модели через `|`; оставьте пустым для общей ситуации;
- `topic_terms` — слова, начала слов или фразы через `|`, которые определяют тему;
- `exclude_terms` — фразы через `|`, при наличии которых статья не подходит;
- `question_examples` — варианты вопросов через `|`; бот распознаёт их при совпадении после приведения регистра и знаков препинания;
- `answer` — точный официальный текст ответа.

Для новой темы добавьте строку со статусом `draft`, проверьте ответ и поменяйте статус на `published`. Для точной новой формулировки добавьте её в `question_examples`. Для более широкого распознавания добавьте слова или начала слов в `topic_terms`; если нужен другой вариант названия оборудования, добавьте его в `equipment_aliases`. Для статей с оборудованием вопрос должен содержать его название. Неоднозначные совпадения направляются сотруднику.

Не публикуйте Google Таблицу «для всех по ссылке». В Google Cloud включите Sheets API, создайте сервисный аккаунт и поделитесь только нужной таблицей с его адресом. JSON-ключ храните локально в `credentials/service-account.json`; эта папка и `.env` исключены из Git. Не пересылайте ключ вместе с репозиторием. Для менеджера добавьте его Google-адрес в настройках доступа таблицы с ролью «Редактор».

В таблице есть вкладка `Инструкция` с описанием полей. Вкладку `Knowledge` не переименовывайте и не меняйте заголовки. Для новой статьи добавьте строку с новым `id`, сначала `draft`, затем после проверки `published`. Не удаляйте чужие правки без согласования. Локальная форма обнаруживает изменение статьи после открытия формы и попросит обновить страницу.

### Сценарий демонстрации без новой технической инструкции

1. Спросите у бота: «Нужен ролик для КАН Ультра». Сначала он направит в сервисный отдел.
2. В редакторе откройте статью `kan_ultra_maintenance` и добавьте в «Варианты вопросов» через `|` фразу «Нужен ролик для КАН Ультра».
3. Сохраните статью и повторите вопрос. Бот вернёт уже утверждённую ссылку на видео.
4. Спросите про обслуживание станции «Тверь»: бот не создаст новую инструкцию.
5. В редакторе откройте «Вопросы без ответа» и покажите запись этого обращения.

## Проверка

`python3 -m unittest discover -s tests -v`

Примеры: КАН Ультра, периодичность обслуживания КИТ, переполнение станции. Вопрос «Как почистить станцию Тверь?» должен получить отказ.

## Журнал обращений

Вопросы и статусы сохраняются в `data/audit.sqlite3` (файл не попадает в Git). Статус `needs_human` означает, что вопрос требуется разобрать сотруднику. Автоматической отправки вопроса сотрудникам на этом этапе нет.
